# Bulk token distribution

The SDK supports batches of 1–20 rows, each with a unique ID, recipient and positive u64 amount in base units. Each row has its own transaction and status. The caller supplies a transport that validates actual public keys and token accounts, builds a standard SPL transfer checked instruction, signs without broadcasting, and returns the signed signature and broadcast callback. Use test networks only.

Persist the journal durably before broadcasting and use exclusive execution (including across tabs/processes). Store bigint amounts as decimal strings and restore them as bigint. Bind the journal to network, mint and sender. Never recreate a journal for a retry. A confirmed row is skipped; an unknown row is reconciled by signature and never re-signed until definitive failure is established. Missing RPC status or timeout is not definitive failure. Failed rows can be retried on a subsequent execution. Display each row's status, signature and error. A crash before broadcast can leave a row unknown indefinitely; do not automatically resend it with a new signature.

This is the SDK orchestration layer, not a wallet transport or distribution screen. Integration must implement the transport and durable journal. Run npm run build --workspace @solo-x/sdk and npm run test --workspace @solo-x/sdk; exercise real wallet and RPC behavior on devnet before enabling distribution.
